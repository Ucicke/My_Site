# ucicke.ru — сайт Ивана Брежнева

Самостоятельный проект портфолио Ucicke на HTML, Tailwind CSS и небольшом
JavaScript-модуле. Для разработки нужны Node.js 20+ и `npm ci`.
Tailwind используется только при сборке: готовый сайт состоит из статических файлов,
без фреймворка или CDN-скриптов. Для публикации — PowerShell, OpenSSH и tar.

## Работа над сайтом

Откройте **эту папку** отдельным проектом в редакторе / Codex.

- `index.html` — тексты, карточки игр, профили, SEO и структура страницы.
- `site-assets/styles.css` — исходные стили и подключение Tailwind; сборка компилирует их в `dist/`.
- `site-assets/site.js` — терминал, небольшое перетаскивание и реакции на наведение.
- `site-assets/cover-*.svg` — собственные графические обложки игр.
- `site-assets/favicon.svg` — собственная иконка сайта.
- `scripts/` — локальный сервер с пересборкой и статическая сборка Tailwind.
- `deploy/` — собственная публикация сайта.

```powershell
npm ci
npm run dev
```

Предпросмотр: http://127.0.0.1:4174/. HTML/CSS/JS сайта пересобираются при изменении;
обновите страницу после сообщения `Website updated.`.
Ссылки `/lifesim/`, `/deadweed/`, `/scroll_hunter/` и `/dark_pool/` ведут на опубликованные игры.

```powershell
npm test
npm run build
```

Сборка находится в `dist/` и содержит только `index.html` и `site-assets/`.
Её можно разместить на любом статическом хостинге. Содержание и ссылки доступны
без JavaScript; интерактивный терминал и анимации используют собственный ES-модуль.
Настройка `prefers-reduced-motion` отключает перемещения и появление при прокрутке.

## Публикация

Локальный `deploy/deploy.env` уже заполнен при переносе и исключён из Git.
Для нового компьютера используйте `deploy/deploy.env.example`, собственный SSH-ключ
и предварительно проверьте обычное SSH-подключение к серверу.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/deploy_site.ps1
```

Скрипт сам собирает сайт и публикует его в отдельный релиз `/opt/ucicke_site/releases/`.
Он меняет только `public_html/index.html` и `public_html/site-assets`, сохраняя
предыдущие версии в `previous-public-files` внутри релиза. Игровые каталоги не входят
в этот деплой. Общий файловый lock исключает гонку с игровыми деплоями.

Для отката возьмите `previous-public-files/index.html` и `site-assets` нужного
релиза. Старые релизы не удаляются автоматически. Не выкладывайте секреты из
`deploy.env` в Git и не заменяйте весь web docroot содержимым `dist/`.
